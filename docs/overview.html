Terila Data Extractor

API Reference · Minecraft 26.3 · protocol 777 · data pack 121.0

This is the API documentation of the extractor that turns a Minecraft 26.3 installation into the complete Terila data set: every registry, every data pack file, every structure template, every protocol table, and the packet-shaped NBT artifacts the server and client consume. The documents it produces are described in the project's README.md; this site describes the code that produces them.

The pipeline is plain and sequential: a context loads the game data, every extractor registered in Extractors is run against it, and the run is published only after every document has been written and validated. Nothing in here is a service; there is no daemon, no database and no background thread pool beyond the extractor executor.

Package guide

Where each kind of work lives
Package Contents
com.terila.extractor.core Run configuration, context, scheduling, output transaction and validation. The machinery, not the data.
com.terila.extractor.extractors The extractor registry, and one subpackage per output family: blocks, items, entities, tags, recipes, worldgen, and so on.
com.terila.extractor.extractors.tags Tag resolution and the two binary tag payloads, including the versioned client registry whitelist.
com.terila.extractor.extractors.registry Registry dumps and the codec pairing that makes a decoded value look like the game's own.
com.terila.extractor.extractors.reports Data generator reports: block state ids, command trees, registry reports, component defaults.
com.terila.extractor.util Wire encoders, NBT helpers, hashing, identifiers and the small string utilities shared by every extractor.
com.terila.extractor.bootstrap Loading the Minecraft runtime outside the game, for head-less runs.
com.terila.extractor.mixin The single server mixin that triggers extraction once the levels are ready.

Notes

  • Binary formats are documented next to the code that writes them, not in a separate format chapter: WireFormat for the packet framing, TagWirePayload for the update_tags payload.
  • A document is only ever replaced as part of a published run. If a run fails, the previous output stays exactly where it was.
  • Warnings are data: TAG_REGISTRY_DRIFT and friends appear in _errors.json and never abort a run.
  • Every number in the extracted documents is checked against the live game by the test suite; this API page documents behaviour, not values.
